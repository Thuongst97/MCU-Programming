NUCLEO-G474RE Board Reference

Every pin the course can reach on the NUCLEO-G474RE: its alternate functions with their AF numbers, its Arduino and Morpho header position, which examples use it, and the parts on the board that can surprise you. The same data covers the STM32G474VET6 (LQFP100), which runs the same firmware.

A.1Interactive pinout

Click a pin to see its alternate functions with their AF numbers (the value you write into GPIOx_AFRL/AFRH), its analog functions, its pin number on the LQFP64 (RET6) and LQFP100 (VET6) packages, and the examples that use it. Type a function into the search box (FDCAN, ADC1, USART1) to find every pin that offers it. Switch to Analog inputs to see which header pins reach an ADC.

⚠️
5 V tolerant is not the same for every pin

Most STM32G474 I/Os are 5 V tolerant as digital inputs, but not while they are in analog mode, and some pins are not 5 V tolerant at all. The I/O structure column of DS12288's pin table (FT, FT_a, FT_f, TT, …) says which is which. Treat any pin you use as an analog input as 3.3 V only, and look up the rest before you connect a 5 V signal.

Pin functions and AF numbers are generated by tools/gen-pins.py from ST's open pin data (the CubeMX database), and tools/check-pins.py checks every AF_<pin>_<signal> constant in the firmware against it. The Arduino map follows ST's NUCLEO BSP and STM32duino variant; the header order follows UM2505. The Morpho headers (CN7/CN10) carry every pin; the pinout lists the ones the course uses there without drawing their positions, so check UM2505 or the silkscreen on yours.

🎭
Analogy

The ST-LINK half of the board is a service hatch built into the car: a diagnostic port, a flashing tool and a dashboard display in one. The STM32 half is the car itself. Most beginners' problems are with the hatch, not the car, which is why Troubleshooting starts there.

A.3Known quirks

PB8 is also BOOT0

On the G474, BOOT0 is not a separate pin: PB8 (Arduino D15) is sampled at reset as long as the option bit nSWBOOT0 = 1, the factory default. If PB8 is high at that moment and nBOOT1 = 1, the chip starts ST's system bootloader instead of your program (RM0440, boot configuration; module 03). An I2C pull-up on D15 does exactly that, which is why example 06 moved I2C to I2C2 on PA9/PA8. The option bits decide it:

⚠️
Change option bytes only on purpose

Setting nSWBOOT0 = 0 makes the chip ignore PB8 and use nBOOT0 instead, which frees the pin; RDP and DBANK live in the same register. Write down how to undo every change before you make it (module 16).

SWD can be switched off by your own program

PA13 (SWDIO) and PA14 (SWCLK) start in alternate-function mode, AF0. A GPIOA_MODER or AFRH write that changes them disconnects the debugger, and you need connect-under-reset to get back in (module 05, Troubleshooting). The course's GPIO helpers and the AUTOSAR Port driver refuse to touch them.

RET6 or VET6?

The NUCLEO carries the STM32G474RET6 (LQFP64). The STM32G474VET6 is the same die in an LQFP100 package: the same 512 KB of flash, 128 KB of SRAM, peripherals and registers, so every example runs unchanged. Only the package differs: more pins are bonded out (all of ports D and E, for example), and every pin has a different package number. The pinout panel shows both numbers; on your own VET6 board, follow its schematic, not the NUCLEO's headers.

Other things to know

  • Errata. ST lists known silicon limitations in errata sheet ES0430. Modules mention the items that affect them (the I2C and FDCAN items in particular).
  • Flash size. The flash size register at 0x1FFF75E0 reports 512 (KB) on this part; the course's linker script says the same.
  • No CAN transceiver. FDCAN1 comes out on PA11/PA12 (Morpho header) as logic levels. You add a 3.3 V transceiver, rated for the CAN FD data rate if you use one (module 12).

Which pins are free?

Search the pinout above for the function you need. Keep PA13/PA14 for the debugger, PA2/PA3 for the virtual COM port, and think twice about PB8 (BOOT0) and PA5 (LD2).
