Appendix: ST's LL Drivers

The course writes registers through the CMSIS header. ST offers two layers on top: HAL, which you met on the setup page, and the Low-Layer (LL) drivers. This appendix shows what LL is, puts it next to the register code you already know, and helps you decide which one a project should use.

⏱ 20 min read🎯 Beginner📂 examples/00-bluepill-blink-uart/ll

D.1What LL is (and isn't)

The LL drivers (stm32f1xx_ll_*.h, part of ST's STM32CubeF1 package) are mostly static inline functions, each wrapping one or a few register accesses. LL_GPIO_SetOutputPin(GPIOC, LL_GPIO_PIN_13) is a single write to GPIOC->BSRR. They add readable names and a little argument packing, not behaviour:

  • no state, no handles, no callbacks, no timeouts: you still write every wait loop yourself;
  • no interrupt handlers: you still write USART1_IRQHandler;
  • a few helper functions (LL_USART_SetBaudRate, LL_RCC_GetSystemClocksFreq) do arithmetic you would otherwise write by hand.

The course's LL build of example 00 uses the same startup code and linker script as the register build and only the header-only parts of LL, taken from the CubeMX-generated HAL folder (examples/00-…/hal/Drivers, the one place vendor HAL code lives in this repository).

🎭
Analogy

LL is a set of labelled light switches on top of the fuse box: flipping "kitchen" is the same as flipping fuse 7, but you no longer have to remember the number. HAL is a smart-home app: it does more for you, and decides some things you might have wanted to decide yourself.

D.2Registers vs LL side by side

The clock setup, written with registers (left) and with LL (right). Read them line by line: almost every LL call has exactly one register statement on the other side.

⚠️
The name does not make it right

LL_FLASH_LATENCY_2 is 0x2: two wait states. The CMSIS macro FLASH_ACR_LATENCY_2 is the mask 0x4, bit 2 of the field, which is not a valid latency on the F1 at all (module 04). Similar-looking names in the two layers can mean different things: when in doubt, check the value in the header against the reference manual.

D.3Registers, LL or HAL?

AspectRegisters (CMSIS)LLHAL

Fit for AUTOSAR MCAL codeyes: MCALs are written at this levelpossible inside an MCALno: overlaps with MCAL responsibilities

A common choice in industry: HAL or LL for prototypes and tools, registers (or the vendor's AUTOSAR MCAL) for production firmware where every line must be reviewed and its timing understood. This course teaches registers so that whichever layer you meet later, you know what it does underneath.
