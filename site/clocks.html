Module 04 · From reset to main

Clocks: RCC, HSE, PLL and Flash Wait States

Every peripheral on the chip counts time in clock cycles. Get the clock tree right and baud rates, timer periods and ADC samples come out exactly as calculated. Get it wrong and things fail in ways that look unrelated. This module covers the STM32F1 clock system end to end.

⏱ 40 min read🎯 Intermediate📂 examples/common/bsp/clock.c

4.1Why clocks matter

A clock is a square wave that tells digital logic when to take its next step. On the STM32F103 one clock source feeds a tree of dividers, and each branch drives a group of peripherals. Three reasons to care:

  • Speed. The core runs at up to 72 MHz, nine times faster than after reset.
  • Correct timing. A UART's baud rate, a timer's period and a CAN bit time are all divided down from a bus clock. If you assume the wrong clock, every derived rate is wrong by the same factor.
  • Power. Current consumption grows roughly with clock frequency, and every peripheral with its clock off costs (almost) nothing (DS5319, supply current tables).
🎭
Analogy

The clock tree is a gearbox. One motor (the oscillator) turns a main shaft (SYSCLK); gears (prescalers) make slower shafts for the slower machines. If you change the motor speed, every machine changes speed with it, unless you also change the gears.

⚠️
The ×2 timer rule

When an APB prescaler is not 1, the timers on that bus get twice the bus clock (RM0008 §7.2). At the course setup, APB1 runs at 36 MHz but TIM2–TIM4 count at 72 MHz. Forgetting this halves or doubles every timer period. Module 07 builds on it.

4.4Flash wait states and prefetch

Flash memory needs time to deliver data. At high clock speeds the CPU would ask for the next instruction before the flash has it, so the flash interface inserts wait states (PM0075 §3.1):

SYSCLKFLASH_ACR.LATENCY
≤ 24 MHz0
24–48 MHz1
48–72 MHz2

The prefetch buffer reads 64 bits ahead while the CPU executes, so straight-line code rarely waits. Branches and data reads from flash still pay the wait states. This is the register right after clock_init_72mhz():

⚠️
FLASH_ACR_LATENCY_2 means bit 2, not two wait states

The CMSIS header defines FLASH_ACR_LATENCY_0, _1 and _2 as the individual bits of the field (values 1, 2 and 4). Writing FLASH_ACR_LATENCY_2 sets the field to 4, which the F1 does not define. Write the number: (2U << FLASH_ACR_LATENCY_Pos). Set it before raising the clock, and lower the clock before reducing it.

4.6Peripheral clock enables

Each peripheral has an enable bit in one of three registers, by bus: RCC_AHBENR (DMA, CRC, flash interface), RCC_APB2ENR and RCC_APB1ENR. Until its bit is set, a peripheral ignores writes and reads back zeros, which is the most common reason for "my register writes don't do anything".

💡
Which bus is it on?

Look the peripheral up in the enable registers above, or in the block diagram. GPIO ports, AFIO, USART1, SPI1, ADC and TIM1 are on APB2; everything else used in this course is on APB1.

4.7Measuring the clock (MCO on PA8)

To check a clock with real instruments, route it to pin PA8 with RCC_CFGR.MCO. The pin can switch at 50 MHz at most, so output HSE (8 MHz) or PLL ÷ 2 (36 MHz), not the 72 MHz SYSCLK (RM0008 §7.2.10).

Example 04's shell has an mco command. Type mco hse and measure PA8 with an oscilloscope, a logic analyser that samples fast enough, or a frequency counter: you should see 8 MHz, and its accuracy tells you how good the crystal is.
