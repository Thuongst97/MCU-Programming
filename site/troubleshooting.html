Troubleshooting

Start from what you see. Each entry lists the likely causes in the order worth checking, and the fix. Most problems are wiring, power or a setting in the debugger configuration.

⏱ Reference🎯 All levels🔎 Symptom first

B.1No ST-Link detected

You see: Error: open failed, LIBUSB_ERROR_ACCESS, or No ST-Link detected.

  1. Is the probe on the bus at all? Linux: lsusb should list 0483:3748 (STMicroelectronics ST-LINK/V2). Windows: Device Manager should show it under Universal Serial Bus devices. If not, try another cable or port: charge-only cables are common.
  2. Linux permissions. The openocd package installs udev rules that give the logged-in user access. Reload them and replug the probe:
  3. Windows driver. Install ST's ST-Link driver package (STSW-LINK009) and replug. If another tool replaced the driver, reinstall ST's.
  4. Another program holds the probe. Only one tool can own the ST-Link: close STM32CubeIDE, CubeProgrammer or a running OpenOCD.

B.2UNEXPECTED idcode on clone chips

You see: UNEXPECTED idcode: 0x2ba01477 and expected 1 of 1: 0x1ba01477.

The probe works and the chip answers. It is just not an ST chip: many Blue Pills carry a compatible clone (CKS32, CS32, APM32) whose debug port reports a different ID. OpenOCD's STM32F1 script checks the ID and stops. Tell it what to expect with the clone configuration, which sets CPUTAPID and then loads the normal one:

⚠️
Don't edit OpenOCD's installed scripts

Editing target/stm32f1x.cfg fixes it on your machine only and is undone by the next update. Keep the difference in the project: bluepill-clone.cfg, and the matching entry in .vscode/launch.json.

B.3Cannot halt target / SWD locked out

You see: the first flash worked, but now Error: init mode failed (unable to connect to the target) or timed out while waiting for target halted.

The probe can only talk to the chip while PA13/PA14 are debug pins and the core is awake. Your program probably took that away right after reset: it wrote SWJ_CFG = DISABLE, reconfigured PA13/PA14 as GPIO, entered Stop/Standby mode immediately, or crashed into a loop with the clocks misconfigured.

Fix 1: boot into the system bootloader (always works)

  1. Set the BOOT0 jumper to 1 and press reset. The chip now runs ST's ROM bootloader instead of your program, so SWD stays free.

  3. Set BOOT0 back to 0, fix the program, flash again.

B.4LED inverted or dim

You see: the LED is on when your code says "off", or it glows dimly.

  • Inverted: expected. The on-board LED lights when PC13 is low. Write GPIO_BSRR_BR13 to turn it on and GPIO_BSRR_BS13 to turn it off.
  • Dim: PC13 is probably still an input with its pull-up or pull-down, so only a tiny current flows. Check that MODE13 in GPIOC_CRH is not 00:
  • Never lights: the port clock is off (RCC_APB2ENR.IOPCEN), or the code configures CRL instead of CRH (pins 8–15 are in CRH).

B.5Garbage on the UART

You see: random characters, or text only before or after a certain point.

  1. Baud rate: the terminal and the firmware must both use 115200 8N1, with no flow control.
  2. The clock the firmware assumed: BRR is computed from the peripheral clock. If the code assumes 72 MHz but the switch failed (the chip still runs at 8 MHz), every bit is 9 times too long. Print the clock status, as example 00 does.
  3. APB1 vs APB2: USART1 is on APB2; USART2 and USART3 are on APB1, which runs at half speed at 72 MHz. Using the wrong bus clock halves or doubles the baud rate.
  4. Wiring: TX → RX, RX → TX, and a common ground. Without GND the signal has no reference and turns into noise.
💡
Measure, don't guess

Send U (0x55) in a loop: on a logic analyser it is a clean square wave whose bit time tells you the real baud rate.

B.6Flash size mismatch

You see: OpenOCD reports 128 KB on a "64 KB" chip, or a program that grew past 64 KB behaves strangely.

Many C8 chips report 128 KB in their flash size register at 0x1FFFF7E0 (RM0008 §30). OpenOCD's stock Blue Pill board file assumes 128 KB as well. The course's bluepill.cfg sets FLASH_SIZE 0x10000 before loading the target, and the linker script declares 64 KB, so a program that does not fit fails at link time with region `FLASH' overflowed. Don't "fix" that by declaring 128 KB: the upper half is not guaranteed. Shrink the program (bluepill-release builds with -Os) instead.

B.7Hangs during clock setup

You see: the program never gets past clock setup, or reports a non-zero clock status.

  • No crystal oscillation: a cracked or missing 8 MHz crystal never sets HSERDY. Code without a timeout hangs forever; the course's code gives up and stays on HSI. Route SYSCLK to PA8 with MCO to check it with a scope.
  • PLL never locks or the switch never happens: the PLL output must stay within the limits in DS5319, and PLLMUL/PLLSRC may only change while the PLL is off.
  • In Renode: the stock STM32F103 platform does not model the clock controller's status bits, so code waits for SWS in vain (our firmware times out with status 3). Use the course's bluepill.repl, which does.

B.8USB not enumerating

You see: the PC does not detect the Blue Pill as a USB device, or only sometimes.

A full-speed USB device announces itself with a 1.5 kΩ pull-up on D+ (PA12). Many Blue Pills fit 10 kΩ (R10) instead, which some hosts tolerate and others ignore, on most boards; check yours. The common fix is an extra resistor of about 1.8 kΩ from PA12 to 3.3 V, giving roughly 1.5 kΩ in parallel. USB examples are not part of this course; remember that USB and CAN cannot run at the same time on this chip.

B.9CAN sends nothing

You see: nothing on the bus, the transmit mailbox never empties, or the error counters climb.

  1. No other node: every CAN frame must be acknowledged by at least one other node. Alone on a bus, the controller resends forever and its transmit error counter rises. Test alone with loopback + silent mode (CAN_BTR.LBKM and SILM) first.
  2. Stuck in initialization mode: bxCAN leaves initialization only after it sees 11 recessive bits on CAN_RX. A floating or shorted RX pin (no transceiver, wrong pin) keeps it there.
  3. Wrong pins: on the Blue Pill, CAN is remapped to PB8/PB9 with AFIO_MAPR.CAN_REMAP = 10 so that PA11/PA12 stay free.
  4. Physical layer: both boards need a transceiver (SN65HVD230 at 3.3 V), a twisted pair, a common ground and 120 Ω at each end of the bus.
  5. Bit timing: both nodes must agree on the bit rate and use a similar sample point. Module 12 has a calculator.
