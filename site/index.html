The 30-second mental model

A microcontroller does exactly what its registers say

There is no operating system underneath your code. At power-on the core reads two numbers from the start of flash, the initial stack pointer and the address of Reset_Handler, and runs from there. Your startup code prepares memory and calls main(). From then on, every peripheral is controlled by writing bits into memory-mapped registers.

Reset → vector table → Reset_Handler → copy .data · zero .bss → main() → RCC->APB2ENR · GPIOC->CRH · GPIOC->BSRR

AUTOSAR later adds structure on top: the same register writes end up inside MCAL drivers, and application code reaches them only through the RTE.

🏭
The big-picture analogy

Picture the chip as a small factory. The CPU core is the only worker. Flash is the recipe book, SRAM the workbench. Each peripheral (timer, UART, ADC) is a machine with a control panel, and the registers are its switches and dials.

The worker never builds a timer from scratch. It walks to the panel and flips the right switches. Learning embedded programming is mostly learning which switches exist and in which order to flip them.
