Module 06 · From reset to main

Interrupts, NVIC, EXTI and SysTick

An interrupt lets hardware call your code the moment something happens: a byte arrived, a timer expired, a button was pressed. On Cortex-M an interrupt handler is an ordinary C function, and the core does the bookkeeping for you. This module explains what the core does, how priorities work, how pins become interrupts, and how to share data with a handler without corrupting it.

6.1Exceptions vs interrupts

Arm calls every event that diverts the CPU an exception. Interrupts (IRQs) are the exceptions that come from peripherals outside the core. All of them are handled the same way, through the vector table.

Exception numberNamePriorityCause
1Reset−3 (fixed)Power-on, NRST, watchdog, software reset
2NMI−2 (fixed)Non-maskable; on the G474 for example the clock security system
3HardFault−1 (fixed)Any fault that cannot be handled elsewhere
4–6MemManage, BusFault, UsageFaultconfigurableAccess violations, bus errors, illegal instructions (module 15)
11SVCallconfigurableThe SVC instruction (RTOS system calls)
14PendSVconfigurableRequested by software; RTOS context switches (module 14)
15SysTickconfigurableThe core's 24-bit timer reached zero

A lower number means a higher priority. Reset, NMI and HardFault have fixed negative priorities, so nothing can block them.

6.2What the core does on entry

When an interrupt is accepted, the Cortex-M4 does in hardware what other CPUs need assembly for (ARM DDI 0403, B1.5.6–B1.5.8). Step through it:

ℹ️
With the FPU: 8 or 26 words

If the interrupted code has used the FPU, the exception frame grows by 18 words: s0–s15, FPSCR and one reserved word. To keep latency low, the Cortex-M4 only reserves that space at entry and saves the registers later, if and when the handler itself touches the FPU (lazy stacking, PM0214). Size every stack for the larger frame.

🎭
Analogy

You are reading a book when the doorbell rings. You put a bookmark in (stacking), answer the door (the handler) and come back to exactly the same line (unstacking). If the phone rings while you are still at the door, you take the call before going back to the book (tail-chaining), instead of sitting down and getting up again.

6.3NVIC priorities and grouping

The NVIC (nested vectored interrupt controller) decides which pending interrupt runs. Each interrupt has an 8-bit priority field, of which the STM32G474 implements the upper 4 bits (__NVIC_PRIO_BITS = 4 in the header): 16 levels, 0 (highest) to 15 (PM0214, NVIC). CMSIS's NVIC_SetPriority(irq, 5) shifts the value into those bits for you.

  • Preemption: a pending interrupt with a strictly higher priority (lower number) interrupts a running handler. Equal priorities wait their turn.
  • Grouping: SCB->AIRCR.PRIGROUP can split the 4 bits into preemption priority and sub-priority (which only orders pending interrupts of the same preemption level). The course keeps all 4 bits as preemption priority, which is also what FreeRTOS expects.
  • Enable and pending: NVIC_EnableIRQ() lets an IRQ through; a peripheral event sets its pending bit even while it is disabled, so a stale event fires immediately when you enable it. Clear the peripheral's flag first.
⚠️
Priority 0 is not "normal"

Every interrupt is priority 0 (the highest) after reset. If you never set priorities, nothing preempts anything and a slow handler delays all the others. Give every IRQ a deliberate priority: fast, short handlers high; slow ones low. SysTick gets the lowest priority from SysTick_Config().

6.4EXTI and SYSCFG_EXTICR

Any GPIO pin can raise an interrupt through the EXTI controller. There are 16 EXTI lines for pins (plus lines for internal events such as the PVD, the RTC and the comparators): line n serves pin n of one port, chosen in SYSCFG_EXTICR1…4 (RM0440, SYSCFG and EXTI). So PA13 and PC13 cannot both interrupt at the same time. SYSCFG needs its own clock (RCC_APB2ENR.SYSCFGEN), and the EXTI registers for lines 0–31 end in 1: IMR1, RTSR1, FTSR1, PR1.

Lines 0–4 each have their own IRQ. Lines 5–9 share EXTI9_5_IRQHandler and lines 10–15 share EXTI15_10_IRQHandler; such a handler reads EXTI->PR1 to find out which line fired. B1 on PC13 is on line 13, so example 01 uses EXTI15_10_IRQHandler.

6.5SysTick time base

SysTick is a 24-bit down-counter inside the core. It reloads from LOAD when it reaches zero and can raise the SysTick exception each time. With HCLK = 170 MHz and LOAD = 169 999, that is exactly once per millisecond. The largest possible reload (224 − 1) gives about 98 ms at 170 MHz.

6.6Sharing data with an ISR

Data shared between a handler and main() is where interrupt bugs hide. Three rules:

  1. Mark it volatile, so the compiler re-reads it every time instead of keeping a copy in a register.
  2. Know what is atomic. A naturally aligned 8-, 16- or 32-bit load or store is a single access on the Cortex-M4. A read-modify-write (x++, reg |= bit) or a 64-bit value is not: an interrupt can land in the middle.
  3. Protect non-atomic sequences with a short critical section, or design them away with one writer per variable.

⚠️
volatile is not a lock

volatile stops the compiler from caching a value; it does not make counter++ atomic. Saving and restoring PRIMASK (instead of a plain __enable_irq()) keeps the critical section correct even when it is called with interrupts already disabled.

6.7A non-blocking cooperative scheduler

Most bare-metal firmware is a super loop: for (;;) calling functions in turn. It stops scaling when some work must happen every 10 ms and other work every second. A small cooperative scheduler fixes that: a table of tasks with periods, run to completion when they are due, timed by SysTick.

"Cooperative" means no task is ever interrupted by another task: each must return quickly. Interrupts still preempt everything. When that model stops being enough, an RTOS takes over (module 14).
