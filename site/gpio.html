GPIO and Alternate Functions

General-purpose I/O is where software touches the physical world. The STM32F1 does it differently from newer STM32 families: four configuration bits per pin, no pull-up register, no alternate-function number. This module covers the F1 model, the electrical limits that protect your board, pin remapping, and the one setting that can lock you out of your own chip.

⏱ 40 min read🎯 Beginner → intermediate📂 examples/01-exti-button-debounce

5.1The F1 GPIO model

Each GPIO port (A, B, C, …) has 16 pins. Every pin is configured with 4 bits: MODE (2 bits) and CNF (2 bits). Pins 0–7 live in GPIOx_CRL, pins 8–15 in GPIOx_CRH (RM0008 §9.2).

MODECNF = 00CNF = 01CNF = 10CNF = 11
00 inputanalog (ADC)floating (reset state)pull-up or pull-downreserved
01/10/11 output, 10/2/50 MHzpush-pullopen-drainalternate function push-pullalternate function open-drain

Two differences surprise people who know newer STM32 parts:

  • Pull direction comes from ODR. In input pull mode (CNF = 10), the pin's bit in ODR chooses the resistor: 1 = pull-up, 0 = pull-down. Example 01 sets it with BSRR.
  • No alternate-function number. On the F1, setting a pin to "alternate function output" connects it to whichever peripheral is enabled on that pin. Inputs used by a peripheral (USART RX, SPI MISO) stay ordinary inputs. Conflicts are resolved by enabling only one peripheral per pin, or by remapping (below).
🎭
Analogy

A pin is a door with a configurable lock. Input floating: the door swings freely in the wind (you read whatever the breeze decides). Input with pull-up: a spring holds it closed unless someone pushes. Push-pull output: you hold the door open or shut yourself. Open-drain: you can only pull it shut; a spring opens it again.

5.2Configure a pin bit by bit

Configure GPIOA pins 0–7 bit by bit. Pick values in the fields, or click bits directly; the C expression shows how you would write it with CMSIS names. Start with the reset value 0x44444444 (every pin floating input) and configure PA0 as input with pull-up, as example 01 does.

5.3ODR, BSRR, BRR and IDR

Five registers move data:

RegisterAccessUse
IDRreadThe level the input buffer sees on each pin, right now.
ODRread/writeThe level the pin drives (outputs), or pull direction (inputs). Writing it is a read-modify-write: not interrupt-safe.
BSRRwriteLow 16 bits set pins, high 16 bits reset pins, in one store. Bits written as 0 change nothing. Interrupt-safe.
BRRwriteReset pins (the same as BSRR's high half).
LCKRspecialLocks a pin's configuration until the next reset.

The LED driver reads ODR to toggle, but writes through BSRR:

💡
Why not ODR ^= mask?

It compiles to load, XOR, store. If an interrupt changes another pin of the same port between the load and the store, the store writes back the old value and the interrupt's change is lost. BSRR avoids the problem because it never reads.

⚠️
Never connect 5 V to a 3.3 V-only pin

PA0–PA7, PB0, PB1, PB5 and PC13–PC15 are not 5 V tolerant. A 5 V sensor output, an Arduino pin or a 5 V UART adapter on one of them can destroy the pin or the chip. Use a level shifter or a resistor divider, or choose an FT pin.

To drive an LED from a normal pin, put a resistor in series: (3.3 V − LED forward voltage) ÷ current. With a red LED (about 2 V) and 4 mA: 1.3 V ÷ 4 mA ≈ 330 Ω. For anything bigger than an LED (a relay, a motor, a 12 V lamp) use a transistor or a driver chip: a GPIO pin is a signal, not a power supply.

5.5AFIO and remapping

The AFIO block (alternate-function I/O) does three jobs: it remaps peripheral signals to different pins, routes pins to EXTI lines, and decides which debug pins stay reserved. Its clock (RCC_APB2ENR.AFIOEN) must be on before you write any AFIO register.

Remapping is all-or-nothing per peripheral: USART1_REMAP moves both TX and RX from PA9/PA10 to PB6/PB7. CAN_REMAP = 10 moves bxCAN to PB8/PB9, which the course uses to keep the USB pins free (RM0008 §9.3).

5.6SWJ_CFG: keeping SWD alive

After reset, five pins belong to the debug port: PA13 (SWDIO), PA14 (SWCLK), and the JTAG-only pins PA15, PB3 and PB4. To use PA15/PB3/PB4 as GPIO, release JTAG but keep SWD:

SWJ_CFGMacroEffect
000(reset)Full JTAG + SWD.
010AFIO_MAPR_SWJ_CFG_JTAGDISABLEJTAG off, SWD still works. PA15, PB3, PB4 free. Use this one.
100AFIO_MAPR_SWJ_CFG_DISABLEJTAG and SWD off. The debugger can no longer connect while the program runs.
⚠️
Never write SWJ_CFG_DISABLE

It locks the debugger out as soon as the line runs, and after every reset. Recovery needs BOOT0 = 1 (Troubleshooting). Also note that SWJ_CFG is write-only and reads back as undefined (RM0008 §9.4.2): when you read-modify-write AFIO_MAPR to change another remap, set SWJ_CFG explicitly in the same write.
