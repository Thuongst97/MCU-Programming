GPIO and Alternate Functions

General-purpose I/O is where software touches the physical world. On the STM32G4 every pin is described by a handful of small fields: a mode, an output type, a speed, a pull resistor and an alternate-function number. This module covers that model, the electrical limits that protect your board, the alternate-function mux, and the two pins you must never touch.

⏱ 40 min read🎯 Beginner → intermediate📂 examples/01-exti-button-debounce

5.1The G4 GPIO model

Each GPIO port (A to G) has 16 pins and sits on the AHB2 bus at 0x48000000 + 1 KB per port. Every pin is configured through separate registers, each holding one field per pin (RM0440, GPIO):

RegisterBits per pinValues
MODER200 input · 01 output · 10 alternate function · 11 analog (the reset state of most pins)
OTYPER10 push-pull · 1 open-drain
OSPEEDR2edge rate, from low (00) to very high (11): faster edges mean more noise and current spikes
PUPDR200 none · 01 pull-up · 10 pull-down
AFR[0], AFR[1]4alternate function 0–15 for pins 0–7 (AFRL) and 8–15 (AFRH)

Two things to know from the start:

  • Analog is the reset state. Unused pins draw the least current in analog mode, so the G4 starts most pins there. A pin you want to read as a digital input must be switched to input mode first. The exceptions are the debug pins PA13, PA14, PA15, PB3 and PB4, which start in alternate-function mode.
  • Pull resistors are separate from the output. PUPDR chooses them, in any mode. The NUCLEO's B1 button already has resistors on the board, and example 01 adds the internal pull-down the way ST's board support does:

The two helpers it calls are three lines each. Every gpio_* function in the course's BSP follows the same pattern: compute the field position, clear the field, write the new value.

🎭
Analogy

A pin is a door with a configurable lock. Input floating: the door swings freely in the wind (you read whatever the breeze decides). Input with pull-up: a spring holds it closed unless someone pushes. Push-pull output: you hold the door open or shut yourself. Open-drain: you can only pull it shut; a spring opens it again. Analog: the door is bricked up, and only a sensor in the wall listens.

5.3ODR, BSRR, BRR and IDR

Five registers move data:

RegisterAccessUse
IDRreadThe level the input buffer sees on each pin, right now. Reads 0 for pins in analog mode.
ODRread/writeThe level each output pin drives. Writing it is a read-modify-write: not interrupt-safe.
BSRRwriteLow 16 bits set pins, high 16 bits reset pins, in one store. Bits written as 0 change nothing. Interrupt-safe.
BRRwriteReset pins (the same as BSRR's high half).
LCKRspecialLocks a pin's configuration until the next reset.

The LED driver reads ODR to toggle, but writes through BSRR:

💡
Why not ODR ^= mask?

It compiles to load, XOR, store. If an interrupt changes another pin of the same port between the load and the store, the store writes back the old value and the interrupt's change is lost. BSRR avoids the problem because it never reads.

5.4Electrical limits

Software can damage hardware here. The numbers that matter live in the datasheet's "Absolute maximum ratings" and "I/O port characteristics" sections (DS12288); learn where they are, and keep a margin:

LimitWhat to doSource
Current per I/O pin and in totalStay at a few mA per pin for logic and LEDs; DS12288 gives the absolute maximum per pin and for all pins together, and the output voltages it guarantees at a given current.DS12288, absolute maximum ratings; I/O port characteristics
Internal pull-up / pull-downWeak: tens of kΩ (DS12288 gives min/typ/max). Fine for a button; too weak for a fast I2C bus.DS12288, I/O port characteristics
5 V toleranceMost pins are marked FT in the pin table: they accept 5 V as digital inputs, but not in analog mode, and they always drive only VDD (3.3 V). Pins without FT never accept more than VDD.DS12288, pin descriptions
Analog inputsAn ADC input must stay between 0 V and VDDA. The pinout's Analog inputs view shows which pins can be ADC inputs.DS12288
⚠️
Check the pin table before you connect 5 V

A 5 V sensor output or a 5 V Arduino shield on a pin that is not FT, or on an FT pin you later switch to analog mode, can destroy the pin or the chip. When in doubt, use a level shifter or a resistor divider. Your NUCLEO's 5 V pin on the power header is an output for shields, not a signal.

To drive an LED from a pin, put a resistor in series: (3.3 V − LED forward voltage) ÷ current. With a red LED (about 2 V) and 4 mA: 1.3 V ÷ 4 mA ≈ 330 Ω. For anything bigger than an LED (a relay, a motor, a 12 V lamp) use a transistor or a driver chip: a GPIO pin is a signal, not a power supply.

5.5Alternate functions (AFR)

Each pin can belong to one of up to 16 peripheral signals. Mode 10 hands the pin to a peripheral; the 4-bit field in AFR says which one. The mapping from (pin, AF number) to signal is fixed in silicon and listed in the datasheet's alternate-function table (DS12288). The same signal is often available on several pins with different AF numbers: LPUART1_TX is AF12 on PA2, for example.

💡
No magic AF numbers

The CMSIS header does not name AF numbers, so the course defines them as constants named after pin and signal, such as AF_PA2_LPUART1_TX, next to the code that uses them. tools/check-pins.py checks every one of them against ST's own pin database, so a typo fails the build instead of leaving a silent pin. Click any pin in the board pinout to see its AF numbers.

5.6Keeping SWD alive

After reset, five pins belong to the debug port in alternate-function mode AF0: PA13 (SWDIO), PA14 (SWCLK), and the JTAG pins PA15 (JTDI), PB3 (JTDO/SWO) and PB4 (NJTRST). The ST-LINK uses only PA13 and PA14 (plus PB3 if you use SWO). The other three you may reconfigure like any pin. There is no special register for this on the G4: the pin's MODER and AFR fields decide.

⚠️
Never change PA13 or PA14

A write such as GPIOA->MODER = 0x00000400 (instead of a read-modify-write of one field) puts PA13 and PA14 into input mode, and the debugger loses the chip as soon as the line runs, and again after every reset. Recovery is a connect under reset, which the NUCLEO supports because its ST-LINK drives NRST. That is why every GPIO helper in the course touches only its own pin's field, and why the AUTOSAR Port driver refuses configurations that take PA13/PA14 away from AF0 (module 20).
