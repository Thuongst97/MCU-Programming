Bootloaders and Flash Programming

A product in the field needs new firmware without an ST-LINK. This module starts with the bootloader ST put into every STM32, then builds our own: programming the chip's flash from code, splitting flash between a bootloader and an application, moving the vector table, jumping safely, and checking every byte with a CRC before it runs.

⏱ 55 min read🎯 Advanced📂 examples/12-uart-bootloader

16.1The built-in system bootloader

Every STM32G474 contains a system bootloader in a 28 KB ROM area called system memory (0x1FFF0000), written by ST and not erasable. With BOOT0 = 1 and the option bit nBOOT1 = 1 at reset, the chip runs it instead of your program (module 03). On the NUCLEO, BOOT0 is pin PB8 (Arduino D15) as long as the option bit nSWBOOT0 = 1, the factory default. The G47x bootloader listens on several interfaces at once: USART1 on PA9/PA10, and USART2 on PA2/PA3, which the NUCLEO wires to the ST-LINK virtual COM port, among others (AN2606, STM32G47x/48x section; check the table for your device and bootloader version).

  • The host sends 0x7F; the bootloader measures the bit time to detect the baud rate and answers ACK 0x79.
  • Frames use 8 data bits and even parity. Every command is followed by its complement as a check byte, and every step is answered with ACK 0x79 or NACK 0x1F (AN3155).
  • Commands read, write and erase flash, set the protection levels and jump to an address.

The open-source stm32flash and ST's STM32CubeProgrammer both speak this protocol, so the USB cable (or a USB-UART adapter on PA9/PA10) is enough to recover a board whose SWD pins you locked (Troubleshooting). Our own bootloader below reuses the ACK and NACK values, so the idea is familiar.

💡
Why write your own?

The system bootloader needs the BOOT0 jumper, accepts any image and has no notion of "is the new firmware complete?". A product needs updates triggered by software, over whatever link it has (UART, CAN, USB), with integrity checks and a fallback when an update is interrupted.

16.2Programming the G4 flash

The flash is programmed through the flash interface registers at 0x40022000 (FLASH_BASE in the header is the memory itself; the registers are FLASH_R_BASE). The rules on the 512 KB STM32G474 (RM0440, FLASH chapter):

  • The control register is locked after reset. Writing the two keys from the reference manual to FLASH_KEYR unlocks it; a wrong key locks it until the next reset.
  • The page size depends on the DBANK option bit: 2 KB pages in two 256 KB banks (DBANK = 1, the factory setting) or 4 KB pages in one bank. Erase sets every bit to 1 (0xFF) and takes tens of milliseconds per page (DS12288, flash characteristics).
  • Programming writes one 64-bit double word at a time, 8-byte aligned. Each double word also stores ECC bits, so it can be programmed only once after an erase: writing a non-erased double word is an error (PROGERR).
  • While an operation runs (BSY), every read from the bank being written, including instruction fetches, stalls the CPU. Code running from that flash simply waits. (In dual-bank mode, code in one bank can keep running while the other is written: read-while-write.)
  • Each page survives about 10 000 erase cycles (DS12288). Don't use flash like RAM.
ℹ️
The flash keys are not in the CMSIS header

The G4 device header names the bits but not the unlock key values, so flash.c defines FLASH_UNLOCK_KEY1/KEY2 with RM0440 as their source (CLAUDE.md rule 19). docs/verification.md lists them among the values to check against the manual.

⚠️
Don't erase the page you are running from

A bootloader that erases its own pages, or an address calculation that is off by one page, deletes the code that is executing. The next instruction fetch reads 0xFFFF, an undefined instruction, and only SWD or the system bootloader can bring the board back. Example 12's WRITE handler checks every offset against the application slot before touching flash.

Analogy

A bootloader is the transfer desk at an airport. It checks your ticket (the image record and CRC) before letting you board the connecting flight (jump to the application). A passenger without a valid ticket stays at the desk until one is issued (update mode).

16.4Relocating the vector table

The core finds every exception handler through the vector table. After reset it reads the table at address 0 (the flash alias), which is the bootloader's. The application's table lives at 0x08004000; without telling the core, the first SysTick interrupt in the application would run the bootloader's handler.

SCB->VTOR (PM0214, "Vector table offset register") holds the table's base address. Its low bits are not implemented, so the table must be aligned to a power of two at least as large as the table: 16 system entries + 102 interrupts = 118 entries × 4 bytes = 472 bytes needs 512-byte alignment. Slot boundaries like 0x08004000 are fine; an arbitrary address is not.

16.7Read-out and write protection

Option bytes (a small flash area at 0x1FFF7800, loaded into FLASH_OPTR and its neighbours at reset; RM0440, FLASH option bytes) set two kinds of protection on the G474, plus the proprietary-code (PCROP) and securable areas this course does not use:

AspectRead-out protection (RDP)Write protection (WRP)
Protects againstreading the firmware through SWD or the system bootloaderaccidental erase or programming
Granularitywhole flash; level 0 (none), 1 (no debug read-out), 2 (permanent: debug disabled for good)up to two page ranges per bank (WRP1A, WRP1B, …), page granularity
Removing itgoing from level 1 back to 0 mass-erases the flash; level 2 can never be removedreprogram the option bytes
Use in example 12for a product, once development is finishedprotect the 16 KB bootloader slot (pages 0–7 with 2 KB pages) so the application can never erase it
⚠️
Test protection on a spare board, and never try level 2

A wrong option byte can leave a board that refuses to be debugged, and RDP level 2 is irreversible by design. Removing level 1 always works, but erases everything. Write down how to undo each setting (OpenOCD's stm32l4x unlock 0, whose driver covers the G4, or STM32CubeProgrammer) before you set it. Also mind nSWBOOT0 and nBOOT1: they decide whether PB8 is BOOT0 at all (board reference).
