CAN with bxCAN (and CAN FD, LIN in Theory)

CAN is the backbone of in-vehicle networks: dozens of ECUs share one twisted pair, any node can talk, the most important message always wins, and a broken node takes itself off the bus. This module goes from the voltages on the wire to the bxCAN registers, then connects two Blue Pills. CAN FD and LIN are covered in theory.

⏱ 60 min read🎯 Intermediate → advanced📂 examples/11-can-two-nodes

12.1Physical layer and transceivers

CAN uses two wires, CAN_H and CAN_L, and reads the difference between them, so noise that hits both wires equally cancels out (ISO 11898-2). There are two bus states:

  • Recessive (logic 1): nobody drives; both wires float at about 2.5 V, difference ≈ 0 V.
  • Dominant (logic 0): a transceiver pulls CAN_H up to about 3.5 V and CAN_L down to about 1.5 V, difference ≈ 2 V.

Dominant always beats recessive: if one node sends 0 and another 1, the bus reads 0. This "wired-AND" is what makes arbitration work. The MCU never touches the bus directly: a transceiver (the 3.3 V SN65HVD230 on the Blue Pill) converts between the CAN_TX/CAN_RX logic pins and the differential pair. A 120 Ω resistor at each end of the bus absorbs reflections.

Analogy

A room full of people with one rule: anyone may shout "no!" (dominant), and silence means "yes" (recessive). If even one person shouts, everyone hears "no". Nobody can be talked over by silence.

12.2The CAN frame

A classic CAN data frame with an 11-bit identifier (ISO 11898-1). Change the ID and the data: the CRC is computed and stuff bits are inserted live. After five equal bits in a row, the sender inserts one opposite bit (red markers) so that receivers always see edges to stay synchronised.

12.3Arbitration and errors

When several nodes start at the same moment, they all send their identifier bit by bit and listen at the same time. A node that sends recessive (1) but reads dominant (0) has lost and stops sending at once, without destroying the winner's frame. The lowest identifier wins. Enter up to three IDs:

Errors are handled the same collective way: every node checks every frame, and a node that detects an error destroys the frame with an error frame (six dominant bits that break the stuffing rule), so everyone discards it and the sender retries. 12.4Bit timing calculator

There is no clock wire, so every node divides each bit into time quanta (tq) and resynchronises on edges. In bxCAN a bit is: 1 tq sync segment, TS1+1 tq before the sample point, TS2+1 tq after it. The quantum is (BRP+1) ÷ PCLK1 (RM0008 §24.7.7). All nodes on one bus must use the same bit rate and similar sample points; 87.5 % is a common target in automotive networks.

12.5The bxCAN peripheral

bxCAN ("basic extended CAN") has three transmit mailboxes, two receive FIFOs of three frames each, and 14 filter banks (RM0008 §24). It has three modes: Sleep (after reset), Initialization (configure BTR and filters) and Normal. Leaving initialization requires 11 consecutive recessive bits on CAN_RX, which is why a missing transceiver keeps it stuck.

12.6Acceptance filters

A busy bus carries hundreds of message IDs, and an ECU needs a few of them. Acceptance filters drop the rest in hardware. In mask mode a frame passes if its identifier matches the filter ID in every bit where the mask is 1; in list mode the filter holds exact IDs. Each of the 14 banks is one 32-bit filter or two 16-bit filters (RM0008 §24.7.4). Try a mask:

12.7Why CAN and USB can't run together

⚠️
CAN and USB cannot be used at the same time on the F103

The USB device peripheral and bxCAN share a 512-byte SRAM buffer and the interrupt vectors 19 and 20 (USB_HP_CAN1_TX, USB_LP_CAN1_RX0) (RM0008 §24.1 and §23). A product with both would need a different MCU. The course remaps CAN to PB8/PB9 anyway, to keep PA11/PA12 free.

The shared vector shows up in code: example 11's receive handler is named USB_LP_CAN1_RX0_IRQHandler.

12.8Two nodes on a real bus

Each node needs a transceiver; CAN_H to CAN_H, CAN_L to CAN_L over a twisted pair, a common ground, and 120 Ω at both ends (many SN65HVD230 modules carry one; check yours).

Before touching the bus, each node tests itself in silent loopback mode: the transmitter is connected internally to the receiver and nothing reaches the pins, so this works without a transceiver or a second node.

12.9CAN FD in theory

CAN FD (flexible data-rate, ISO 11898-1:2015) keeps arbitration at the classic bit rate, then switches to a faster rate for the data phase and allows up to 64 data bytes. The F103's bxCAN does not support CAN FD; worse, a classic controller treats an FD frame as an error. Mixed networks need FD-tolerant or FD-capable controllers everywhere.

12.10LIN in theory

LIN is CAN's cheap little sibling for simple functions (switch panels, mirror motors, rain sensors). It is a single wire at up to 20 kbit/s with one master that runs a fixed schedule table and polls slaves; slaves never speak unasked, so there is no arbitration. A LIN node is often just a UART plus a transceiver, which is why the F1's USART has a LIN mode (module 08).
