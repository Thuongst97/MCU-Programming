What Is a Microcontroller?

A microcontroller is a whole computer on one chip: CPU, memory and peripherals, with no operating system unless you bring one. This module builds the mental model the rest of the course relies on: where things live in memory, what a register really is, and how C turns into bits on a pin.

⏱ 35 min read🎯 Beginner📂 examples/00-nucleo-blink-uart

1.1MCU vs MPU vs SoC

If you come from Android or Linux, you have been programming microprocessors (MPUs): fast application cores (Cortex-A) with a memory management unit, gigabytes of external DRAM, and an operating system that hides the hardware behind drivers and system calls. A microcontroller (MCU) sits at the other end:

AspectMCU (STM32G474)MPU (a Cortex-A head unit)
Memory512 KB flash + 128 KB SRAM on the chipGBs of external DRAM, eMMC/UFS storage
Address translationNone: an address is a physical locationMMU with virtual memory per process
SoftwareYour program, from reset (bare metal) or on a small RTOSLinux or Android, apps in processes
Start-up timeMicroseconds to main()Seconds to a usable system
Hardware accessWrite a register directlyThrough a kernel driver
TimingPredictable to the clock cycleBest effort, caches and scheduling jitter
PowerMilliamps running, microamps asleepWatts

A modern car contains both. The infotainment head unit is an MPU-class SoC (system on chip) running Android Automotive. Door modules, lighting, seat and climate controllers, the brakes and the engine are ECUs (electronic control units) built around microcontrollers, often dozens per car, talking over CAN and LIN. AUTOSAR Classic, the end goal of this course, is written for those MCU-based ECUs.

🎭
Analogy

An MPU running Android is a large office building with a reception desk: you ask the receptionist (the kernel) and someone else flips the switch. A microcontroller is a workshop where you are alone with the machines. Nobody stops you, nobody helps you, and every switch on the wall is one you can reach.

1.2Inside the STM32G474RE

The STM32G474RET6 on the NUCLEO-G474RE packs an Arm Cortex-M4 core with a floating-point unit, running at up to 170 MHz, 512 KB of flash for the program, 128 KB of SRAM for data, and a large set of peripherals: GPIO, timers, USARTs and an LPUART, SPI, I2C, five 12-bit ADCs, DACs, comparators, op-amps, three FDCAN controllers, USB, two DMA controllers with a request multiplexer (DMAMUX), and watchdogs (DS12288). The STM32G474VET6 is the same silicon in a 100-pin package: everything on this site applies to it, only the package pin numbers differ. Hover over a block to see how it connects:

Three things in this picture matter for everything that follows:

  • Buses have speeds and enable registers. The AHB runs the core, memories and DMA at up to 170 MHz. GPIO ports and the ADCs sit on AHB2. Other peripherals hang off two bridges, APB1 and APB2, both up to 170 MHz on the G4. Which bus a peripheral sits on decides which clock it gets and which enable register (RCC_AHB2ENR, RCC_APB1ENR1, RCC_APB2ENR, …) turns it on.
  • DMA is a second bus master. It moves data between peripherals and memory while the CPU does something else. On the G4 a DMA channel only reacts to a peripheral once DMAMUX connects the two (module 09).
  • Everything is clock-gated. After reset almost every peripheral has its clock off to save power. Turning it on is always step one (module 04).

1.3The memory map

The Cortex-M4 sees one flat 32-bit address space: 4 GB of addresses, from 0x00000000 to 0xFFFFFFFF. Most of it is empty. Flash, SRAM and every peripheral register are given fixed addresses in it by the chip's designers (RM0440, memory map). Click a region:

ℹ️
Why the program starts at 0x08000000 and also at 0

After reset the core fetches its first two words from address 0. In the normal boot mode the chip maps (aliases) the main flash at address 0, so the same bytes appear at 0x00000000 and at 0x08000000. Another boot mode maps ST's bootloader in system memory there instead. On the G4 the choice comes from the PB8-BOOT0 pin and option bits (RM0440, boot configuration; module 03).

⚠️
Three RAMs, one of them special

SRAM1 (80 KB) and SRAM2 (16 KB) sit back to back at 0x20000000, so the linker sees one 96 KB region. The 32 KB CCM SRAM at 0x10000000 is wired to the core's own buses: fast for code and data, but the DMA controllers cannot reach it. Never put a DMA buffer there.

1.4Registers and volatile

A peripheral is controlled through registers: 32-bit words at fixed addresses in the peripheral region. Writing to such an address does not store data in memory. It changes the hardware: turns on a clock, drives a pin, starts a conversion. Reading returns the hardware's current state. This is called memory-mapped I/O.

Three ideas hide in that line:

  1. volatile tells the compiler that this location can change, or has side effects, outside the program's control. Without it, the optimiser may merge, reorder or delete accesses it thinks are redundant, such as writing the same register twice or reading a status flag in a loop.
  2. Read-modify-write. |= reads the whole register, sets one bit and writes it back, so the other 31 bits keep their value. If an interrupt changes the same register between the read and the write, its change is lost. Module 06 shows how to avoid that.
  3. Masks and shifts. Fields are groups of bits. You clear a field with &= ~MASK and set a value with | (value << POS). The header provides _Msk and _Pos for every field.

1.5The Cortex-M4 core

The Cortex-M4 is Arm's ARMv7E-M core for microcontrollers (ARM DDI 0403, ARM DDI 0439, PM0214). What you need to know as a programmer:

  • Thumb-2 only. It executes a mix of 16- and 32-bit instructions. There is no "ARM state"; trying to enter it causes a fault (module 15).
  • Registers r0–r12, the stack pointer sp (two of them: MSP and PSP), the link register lr (return address), the program counter pc, and the status register xPSR.
  • NVIC, the interrupt controller, is part of the core. The STM32G474 has 102 interrupt lines and uses 4 priority bits, so 16 priority levels.
  • SysTick, a 24-bit timer inside the core, gives every Cortex-M a standard time base.
  • A single-precision FPU with its own 32 registers (s0–s31), plus DSP instructions (multiply-accumulate, saturating maths). float is fast; double is still done in software.
  • Exceptions are C functions. The core saves the registers a C function may clobber before it calls an interrupt handler, so handlers need no assembly (module 06).
⚠️
The FPU is off after reset

The build uses -mfloat-abi=hard, so the compiler may emit floating-point instructions anywhere it likes, even for copying a struct. Until the startup code enables coprocessors CP10 and CP11 in SCB->CPACR, the first such instruction raises a UsageFault (NOCP). The course's startup does this before it touches .data (module 03).

💡
Small is still small

128 KB of RAM is a lot for an MCU and nothing next to a phone. A single printf("%f") can pull in many kilobytes of library code, and a 4 KB array on a task's stack can overflow it. The course avoids printf and dynamic allocation for these reasons.

1.7Key takeaways

  • An MCU is CPU + flash + SRAM + peripherals on one chip, running your code from reset with no operating system.
  • Everything has an address. Peripheral registers live at 0x40000000 and up (GPIO at 0x48000000); writing them changes hardware.
  • Use the CMSIS names (RCC->AHB2ENR, RCC_AHB2ENR_GPIOAEN), never raw addresses, and remember that they are volatile.
  • Peripherals sit on buses with different enable registers and start with their clock off.
  • The Cortex-M4F has an FPU that must be switched on first, and DMA cannot reach CCM SRAM.
