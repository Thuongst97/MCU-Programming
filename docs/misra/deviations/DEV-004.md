# DEV-004: compiler-abstraction macros with unparenthesised parameters

| Field | Value |
|---|---|
| Rule | MISRA C:2012 Rule 20.7 (required) |
| Scope | `autosar/include/Compiler.h` only |
| Raised by / date | MCU Academy authors, Phase 6 |
| Approved by / date | self-review, Phase 6 |

## Why the rule cannot be followed here
`FUNC(rettype, memclass)`, `P2VAR(ptrtype, memclass, ptrclass)` and their siblings
(AUTOSAR_CP_SWS_CompilerAbstraction) take *types* and memory-class keywords as arguments.
Putting a type in parentheses is a syntax error, so the parameters cannot be parenthesised.

## Why it is safe
The macros are expanded only in declarations, never in expressions, so operator precedence
(what the rule protects against) cannot apply.

## How it is marked in code
Scoped in `tools/run-misra.py` (SCOPED) to `Compiler.h`.

## Review
When the compiler-abstraction header changes.
