# DEV-001: #include of the memory-mapping header between code

| Field | Value |
|---|---|
| Rule | MISRA C:2012 Rule 20.1 (advisory) |
| Scope | `autosar/` and `capstone/turnlight/stage3-autosar/`: only `#include "<Msn>_MemMap.h"` lines |
| Raised by / date | MCU Academy authors, Phase 6 |
| Approved by / date | self-review (docs/autosar-self-review.md), Phase 6 |

## Why the rule cannot be followed here
AUTOSAR memory mapping (AUTOSAR_CP_SWS_MemoryMapping) places code and data in sections by
including the module's MemMap header before and after each group of definitions, with a
`<MSN>_START_SEC_<X>` / `<MSN>_STOP_SEC_<X>` define. The includes are therefore between
declarations by design. Every AUTOSAR stack carries this deviation.

## Why it is safe
The MemMap headers contain only preprocessor directives (they are generated by
`tools/gen-autosar-cfg.py`). `MemMap_Check.h` stops the build when a section is not closed or
sections nest, and `tools/check-autosar.py` checks that every START has its STOP.

## How it is marked in code
Not marked per line: `tools/run-misra.py` (SCOPED) limits the deviation to these include lines.

## Review
At every change of `tools/gen-autosar-cfg.py` or `MemMap_Check.h`.
